# IT8620 fan1 and fan2 controls

The optional fan broker adds Full / Auto / Manual switches and live 0–255 output sliders to the **IT8620 it87.2624 fan1/fan2 cards only**. All other controllers and channels remain read-only. This does not identify these channels with physical SYS_FAN2 or SYS_FAN3. Previous pulses established PWM1 → fan1 and PWM2 → fan2 response, but physical header assignments remain unverified. The previous shutdown occurred during PWM4 testing; no control path here probes or writes PWM3–6, loads a driver, changes PWM frequency/polarity, or changes a firmware curve.

## Dashboard behavior

- Full writes `pwmN_enable=0`. Auto writes `2`. Manual reads the current duty, writes enable `1`, then applies that observed duty so it does not select an old unrelated manual value.
- The slider displays the reported `pwmN` register, including automatic updates. Its range is integer 0–255. It is editable only in Manual mode with fresh readings, a healthy broker and an unlocked control token. Dragging sends one change on release; keyboard and focus-out edits also commit. Zero asks for confirmation because it may stop the fan.
- Full mode bypasses normal PWM regulation on this chip. The reported duty register may retain its earlier value even though Full mode drives full speed. The slider is a register reading, not measured voltage, percent of RPM or a target RPM.
- Both controlled cards remain visible at zero RPM when controls are enabled, so a stopped fan's controls do not disappear. Other zero-RPM inputs retain the existing hide/show behavior.
- Use the existing separate **engine control token** in the fan unlock form. The viewer token alone cannot change fans. Both tokens stay in tab memory; disconnect/unmount clears the form. A denied control request clears the management credential. Conflicts/timeouts refresh observed state and never automatically replay a write.

The existing telemetry collector adds read-only `pwm` and `pwm_enable` fields only for these two identity-matched channels. A broker status poll every two seconds supplies the control session/version and health. Hardware readings may be cached by the kernel for about 1.5 seconds. Windows mock telemetry cannot operate real fans. No broker means disabled controls and normal monitoring.

## Host boundary and safety behavior

The API stays non-root and gets no writable sysfs, systemd or Docker mount. A **separate, optional root broker** listens only on `/run/p100-lab-fans/agent.sock`. Its fixed allowlist accepts only `fan1` or `fan2`, a mode enum or one integer duty, explicit confirmation and the current session/revision. It checks the X99-SLI-CF/Gigabyte board identity, IT8620 chip identity, device subtree and attribute path on every hardware access. Requests cannot supply paths, executables, shell strings, other register names or temperature/frequency settings. IPC authentication uses a new private secret distinct from viewer, engine-control and existing engine-agent IPC secrets. Replies contain readings, health and version, never secret values or host paths.

The broker serializes access with a non-queuing lock. A stale session/revision is rejected; reload/restart invalidates old commands. Strict HTTP validation independently rejects unknown fields, boolean/nonnumeric/out-of-range duty values and other channels. Authenticated control attempts are recorded in the existing audit table without credentials. A lost acknowledgement is treated as unknown and requires fresh observed state.

While running, a shared host loop checks both Tesla P100 temperatures every two seconds through a fixed read-only NVIDIA query. At **75°C**, unavailable/invalid GPU monitoring, or three consecutive guard observations of zero RPM in nonzero Manual mode, it requests and verifies **Full on both channels**. A failed control write/readback also requests Full. This overrides manual or automatic selection; the UI reports the safety override. Once monitoring recovers, an operator can explicitly choose a new mode. There is no automatic return to the earlier manual value. Output zero is accepted only as an explicit user action and is still covered by GPU temperature monitoring. This is a fallback to maximum cooling, **not an inference-stop mechanism or a calibrated fan curve**.

Startup refuses unapproved hardware and forces orphaned Manual outputs to Full. Clean service shutdown forces both Full. The supplied systemd unit also runs the fixed Full-only helper after exit, and uses a watchdog so a hung broker is stopped/restarted with Full requested. This cannot guarantee a response to an OS/power failure, missing hardware or a broken driver. The root broker and its installed code, sysfs driver, NVIDIA utility and systemd unit are trusted components. The sysfs writable mount covers the controller subtree; the code-level allowlist is what excludes the other channels. Driver register operations may affect a shared register while preserving unrelated channel bits. Prior PWM1/2 success is not proof of safety for every future configuration.

## Separate installation and acceptance after review

Nothing in API startup installs or starts the broker. Base Compose remains monitoring-only. Do not change the existing fan driver, kernel options, PWM4 or firmware settings as part of admission.

1. Record board/controller identity, current PWM1/2 modes/duties/RPM, GPU temperatures, current dashboard revision and saved data. Keep the existing hardware healthy and arrange a short idle host acceptance window.
2. Install the reviewed package in an independent **root-owned, non-writable-by-API** `/opt/p100-lab-fans/venv` runtime. The broker uses only the Python standard library. Verify that `python -I -m lab.fan_agent --help` resolves this sealed code. Do not replace the engine-agent runtime or native engine units.
3. Reuse the existing API group GID 10001 only after checking it has no untrusted host members. Create `/etc/p100-lab-fans` as root:10001 mode 0750 and a random ASCII IPC secret of at least 32 characters in `ipc-token`, root:10001 mode 0640. Keep it distinct from all existing secrets; preserve existing tokens. No credentials belong in source, command arguments or frontend files.
4. Review/install [the root service example](../deploy/fan-agent/p100-lab-fans.service.example). Its writable sysfs scope is only `/sys/devices/platform/it87.2624`; it has no capabilities and no network address family except Unix sockets. It still needs the existing NVIDIA device access for the read-only health query. Do not restart Docker, Netdata, SSH or any engine. Normal first startup with healthy monitoring and both channels Auto makes no control write. Orphaned Manual or failed monitoring causes Full by design.
5. Build a **separate candidate dashboard** using [compose.fans.yaml](../compose.fans.yaml), with its own disposable data copy and no public port. Supply the existing engine-control secret using `LAB_ENGINE_CONTROL_TOKEN_FILE`. Only the fan socket directory and read-only secret file are added to the API mounts. Keep all existing GPU, engine, history and model-library overrides.
6. Verify viewer-only denials, bad secret, other-channel/path/value denials and stale-session handling using fixtures first. With hardware idle, verify only fan1/fan2: Auto readings, Full response, Manual entry at the observed output, a reviewed modest adjustment, Auto restoration, independent channel operation and a zero-RPM card remaining accessible. Establish safe manual limits before testing low outputs; no hardware zero-output test is part of this PR. Do not sweep unverified channels.
7. Verify loss-of-monitoring/write failure/stall/watchdog fallback using a **synthetic hardware fixture**, never by modifying real sensor readings or overheating the GPUs. Verify the effective systemd write/device policy and socket/secret permissions on Ubuntu. Check disconnect/reconnect, browser refresh, API read-only mounts, data preservation and existing engine work. Record final modes, RPM and temperatures before admitting the candidate and enabling boot startup.
8. Only after acceptance, explicitly replace the lab dashboard and enable the new broker if boot persistence is wanted. This is a separate operator deployment; no reboot is required. No automatic merge/deploy is supplied.

Rollback: stop and disable the broker (the exit helper leaves both channels Full), remove only the fan Compose override, and restore the previous dashboard. With the broker stopped and both GPUs below 60°C, the reviewed operator helper `sudo /opt/p100-lab-fans/venv/bin/python -I -m lab.fan_agent --restore-auto` restores and verifies Auto on these two channels, falling back to Full on write/readback error. It refuses unavailable monitoring or GPUs at/above 60°C before any write. Preserve the RPM driver and its existing boot entry. Never run the retired all-channel mapping scripts.

No dependencies, engine code or model weights are added by this feature; the lab remains Apache-2.0.
